# Conventions

***A convention is a standardized agreement that the hardware, OS, compiler, runtime, and humans all follow so code behaves predictably.***

Everything we often treat as a “rule” or “mechanism” in low-level systems is really just a convention.

An ABI is where these conventions are formally written. The ABI (Application Binary Interface) is the formal specification of a set of conventions that all code targeting a platform must follow to interoperate correctly.

## Calling Conventions

Registers are fast, low-level storage locations inside the CPU. While x64 offers 16 general-purpose registers, their usage is often ruled by conventions. This is because programmers rarely write raw assembly. Everything is generated by the compiler, which makes standardization of resources necessary.

Primarily, there are two **calling conventions**:
  1. Function call convention
  2. System call convention

As long as we are not writing code which has to cross-compatible or follow standard principles, we can use these registers however we want.

On Linux 64-bit, the most common calling convention is the **System V AMD64 ABI**.

### Function Call Convention

| Argument   | Register | Description      |
| :-------   | :------- | :----------      |
| Argument 1 | `rdi`    | First parameter  |
| Argument 2 | `rsi`    | Second parameter |
| Argument 3 | `rdx`    | Third parameter  |
| Argument 4 | `r10`    | Fourth parameter |
| Argument 5 | `r8`     | Fifth parameter  |
| Argument 6 | `r9`     | Sixth parameter  |

### Syscall Convention

| Register | Purpose/Convention |
| :------- | :----------------- |
| rax | Accumulator; return values, syscall # |
| rbx | Base register; often callee-saved |
| rcx | Counter for loops, shifts |
| rdx | Data register; I/O, syscall args |
| rsi | Source index; memory ops, args |
| rdi | Destination index; memory ops, args |
| rbp | Base pointer; stack frame reference |
| rsp | Stack pointer; top of the stack |
| r8  | 5th syscall argument |
| r9  | 6th syscall argument |
| r10 | 4th syscall argument |
| r11 | Temporary scratch for syscall |
| r12–r15 | Callee-saved; general-purpose |

*Caller* is the function that calls a function. The function being called is the *callee*.

When a register is **callee-saved**, the callee function must preserve the state of that register if it wants to use it and restore its state before returning.

When a register is caller-saved, the caller function must preserve its state if it wants to use it because a function call in-between might use it.

To successfully invoke a system call, the data must be placed in these registers. Otherwise, the kernel will not interpret our request correctly.

## Stack Frame Conventions

1. **Prologue/Epilogue conventions**: How registers are saved/restored, how stack alignment is maintained.
2. **Shadow space/red zones**: x86-64 SysV uses a 128-byte red zone; Windows x64 uses shadow space.

These are conventions on top of the calling convention to ensure debuggers and exception handlers work consistently.

## Memory Alignment Conventions

1. Struct alignment and padding rules.
2. Stack alignment requirements (16-byte aligned on x86-64 for SSE instructions).
3. Heap object alignment rules (malloc may guarantee 8/16-byte alignment).

These are conventions to satisfy hardware expectations, vectorization, and performance guarantees.
